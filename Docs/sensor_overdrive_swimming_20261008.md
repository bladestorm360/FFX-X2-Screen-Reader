## Sensor renderer and reader

It requires target mode at current battle window
+2 equals 1, enemy ID20..27, and either 78FA30 equals -1 with 78F9E0 equals 1, or
the native Scan flag (`chr+616 & 1`). `78FA30` checks the living active party's
equipment, so the game reveals Sensor information party-wide. Immunity and
debug overrides stay native. The renderer `8939A0` also checks hide-UI state.

`79ADE0` reads `chr+5D0` current HP; `79AE00` reads `chr+594` maximum HP.

speech always used the pre-effect percentage source at `chr+6E4`. Numeric
Sensor speech now uses the same displayed current/max fields, and refreshes
when reveal state or turn/window ownership changes, even on the same target.
Ordinary undisclosed targets keep their existing percentage readout.

`8975C0`, `894AB0` and Fahrenheit's MIT `ChrRam`/`ElementFlags` agree on
weakness `+5DD`, absorption `+5DC`, nullification `+5DA`, resistance `+5DB`.
The four rendered icons are Fire1, Lightning4, Water8, Ice2, in that order;
hidden Holy bits are omitted. `899F40` builds the popup status rotation using
hexadecimal native text IDs1006,1012,1020, plus the corresponding status bit/
byte indexes. Its description is `78F810(target,1)`, including battle-specific
overrides. The reader uses that getter and the central native macro parser.
It does not read the separate full Scan stats/description (`target,2`).

uses the same dispatcher. Enemy highlight assembles affinities/statuses/help;
reading keys browse the existing snapshot. The visibility callback confirms
or clears the buffer. Capture predicates read
only validated copied ownership and native fields, without calling getters
on input threads. Target/window/actor/generation/visibility changes invalidate

Full relocation-masked getter/visibility bodies and independently decoded

## Verified overdrive behavior

Native `892290` tests Tidus's signed cursor word at state base+14 against the
inclusive success bounds at +8/+10, before advancing the cursor. Manual cues
beep on entry into that interval, once per traversal, directly from that
processor. A separate copied SDL beep channel lasts40ms at880Hz; navigation
pause cannot cancel it merely because battle is active. Explicit context
cancellation, focus/generation changes and the saved Miscellaneous Overdrive
cues setting remain authoritative. No timer or passive memory watcher.

Native state fields are words, with an adjacent coordinate; assist writes now
use the correct width. Tidus and Auron advance through native success phase5.
`898A40` maps Auron command IDs22/32/42/52 (hex) to his four native input
sequences; all share `890EE0`, so all four use the same success handling.
Lulu retains native16-cast assist/phase6. With assist off, ordinary native
stick/button processing stays intact and cast increases are read afterward.
