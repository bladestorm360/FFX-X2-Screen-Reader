## Ownership and handoff (source-confirmed)

- `physical_gamepad.cpp` starts one exclusive SDL owner worker. It pins the containing module for process lifetime, parks until readiness is requested, then initializes SDL and owns all SDL event/gamepad calls. It pumps on a 4 ms loop and handles at most 16 queued events per pass.
- Game/native callbacks use bounded atomic snapshot/queue operations. They consume copied `Frame`/`Edge` values and publish copied rumble commands; they do not receive SDL handles. Frames contain primitive state plus timestamp, device/focus generations, connection and overflow/freshness indicators. Edge and rumble queues have fixed capacities (64 and 16).
- Rumble commands carry device/focus generations and timestamp. The owner executes only matching commands no older than 250 ms, preventing stale commands crossing focus/device lifetimes. Queue pressure marks the frame and the controller bridge falls back to native input; stale snapshots likewise relinquish ownership. Focus changes and disconnect/reconnect reset or invalidate state.
- `sdl_runtime.cpp` declines an already-loaded SDL3 instance or initialized SDL backend, validates required exports, exact SDL 3.4.4 and main-thread initialization conditions, and leaves a loaded module for process lifetime.
- Navigation audio waits for audio readiness only on its separate pinned audio-device worker. Device opening is independent of the controller owner; SDL audio callbacks process copied commands/state. Native and callback publication paths are intended to remain bounded and nonwaiting. The fake fixture explicitly checks native publication remains prompt while initialization/audio open is held.
- No join or unload path is present in the reviewed owner startup; thread handles are closed after creation and modules are pinned. This is deliberate process-lifetime ownership, not verified shutdown behavior.

## Fixture and reported checks

`run_sdl_owner_tests.bat` builds in `install\sdl-owner-tests`, compiles x86 with `/W4 /WX`, and runs seven isolated fake-SDK cases: `normal`, `init`, `audio`, `version`, `owner`, `preloaded`, and `pads`. The fake `SDL3.dll` is built and used only in that test directory; the batch file states it is never deployed to the game. The fixture checks native-input handback, bounded/nonwaiting publication, copied quick button/trigger edges, keyboard-vs-controller recency, focus and queue-pressure behavior, stale-owner recovery, device-lifetime rumble filtering, independent audio opening, zero SDL calls on the simulated native main thread, and no fake SDK affinity violations.

`work/sdl-owner.log` records successful x86 compilation and PASS for all seven fake cases. The fixture source checks zero SDL calls on simulated native main and zero affinity violations; the log itself does not print those counters. `work/sdl-controller.log` records a real SDL 3.4.4 virtual gamepad and native XInput bridge fixture PASS. `work/sdl-audio.log` records dummy-stream production mixer and navigation cue fixture PASS. `work/sdl-input.log` records keyboard/context and DirectInput discovery fixture PASS. These legacy virtual/dummy/single-owner fixtures do not prove production dedicated-worker ownership or real device/audio behavior.
